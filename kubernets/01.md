# AWS EKS - Core Objects

EKS Cluster:
EKS Control Plane -> Contains Kubernetes master components like etcd, kube-apiserver, kube-controller. It's a managed service by AWS
Worker Nodes & Node Groups -> Group of EC2 Instances where we run our Application workloads
Fargate Profiles (Serverless) -> Instead of EC2 Instances, we run our Application workloads on Serverless Fargate profiles
VPC -> With AWS VPC we follow secure networking standards which will allow us to run production workloads on EKS

### EKS Cluster

# EKS Controll plane

1. EKS runs a single tenant kubernetes control plane for each cluster, and control plane infrastructure is not shared across clusters or AWS accounts.
2. This control plane consists of at least two API server nodes and three etcd nodes that run across three Availablity Zons within a Region.
3. EKS automatically detects and replaces unhealthy control plane instances, restarting them across the Availablity Zons within Region as needed

# Worker Node & Node Groups

1. Worker machines is Kubernetes are called nodes. these are EC2 instances
2. EKS worker nodes run in our AWS account and connect to our cluster's control plane via the cluster API server endpoint
3. A node group is one or more Ec2 instances that are deployed in an EC2 Autoscaling group.
4. All instances in a node group must
   a. be the same instance type
   b. Be running the same AMI
   c. use the same EKS worker node IAM role

# Fargate profiles

1. AWS fargate is a technology that provides on demand, right-sized compute capacity for containers.
2. With fargate, we no longer have to provision, configure, or scale groups of virtual machines to run cantainers.
3. Each Pod running on fargate has its own isolation boundary and dose not share that underlaying kernel, CPU resources, memory resources, or elastic network interface with another pod.
4. AWS specially built Fargate controllers that recognizes the pods belonging to fargate and schedules them on fargate profiles.
5. We will see more in our fargate learning section

# VPC

1. EKS uses AWS VPC network policies to restrict traffic between control plane components to within a single cluster.
2. Control plane components for a EKS cluster cann't view or receive communication from from other clusters or other AWS accounts, except as authorized with kubernetes RBAC policies.
3. This secure and highly-available configuration makes EKS reliable and recommended for production workloasds
